0Prerequisites & IICS Account Setup
What is IICS? Informatica Intelligent Cloud Services is a cloud-based ETL platform. You build Mappings (transform logic) and Mapping Tasks (executable jobs) entirely in a browser.

What You Need Before Starting

  • An IICS account (free trial at dm-us.informaticacloud.com)
  • 4 CSV source files uploaded to a shared folder on your machine or cloud storage (S3 / SFTP)

1Create Flat File Connections in IICS
You need one Source connection pointing to your CSV folder and one Target connection pointing to your Output folder. In IICS these are both Flat File connections.
  1. Log in to IICS → Click Administrator in the top menu.
    • Navigate to Connections > New Connection
  2. Create connection SRC_FLATFILE
    • Type: Flat File
    • Runtime Environment: your Secure Agent (or Hosted Agent for trials)
    • Directory: folder path where your 4 source CSVs live, e.g. C:\datagen\Source\
    • Click Test Connection → should say Connection Successful
    • Click Save
  3. Create connection TGT_FLATFILE (same steps, different directory)
    • Directory: C:\datagen\Output\
    • Test and Save
Tip: If you are using a local file system, make sure the Informatica Secure Agent is installed on the same machine. Download it from IICS > Administrator > Runtime Environments.

    • Connection: SRC_FLATFILE

TASK 1 & 2 TGT_CLEAN_SALES.csv & TGT_REJECTED_SALES.csv — Cleansing Pipeline
Goal: Read the dirty file, apply 8 cleansing rules, route valid records to TGT_CLEAN_SALES.csv and invalid records to TGT_REJECTED_SALES.csv. Then merge with the already-clean sales_transactions.csv.

Pipeline Flow

→

→

Step-by-Step in IICS Mapping Designer

  1. Create a New Mapping
    • In IICS → Data Integration → New → Mapping
    • Name it: M_CLEAN_DIRTY_SALES
    • Click Create
  2. Add Source 1 — Dirty Transactions
    • Drag Source transformation to canvas
    • In properties → Connection: SRC_FLATFILE
    • Source Object: sales_transactions_dirty.csv
    • All 7 columns should appear in the Fields tab
  3. Add Expression Transformation — EXP_CLEANSE
    • Drag Expression onto canvas, connect from Source 1
    • Name: EXP_CLEANSE
    • Pass all incoming fields through (Add them as passthrough)
    • Add new Output fields:
    New Fields to Add in EXP_CLEANSE
    Output FieldExpressionPurpose
    QTY_CLEAN ABS(QUANTITY) Convert negative qty to positive
    DISC_CLEAN ABS(DISCOUNT_PERCENT) Convert negative discount to positive
    DATE_CLEAN See formula below Standardise date to MM/DD/YYYY
    IS_VALID See formula below 1 = valid, 0 = reject
    REJECTION_REASON See formula below Human-readable reject text

    DATE_CLEAN formula

    -- Detect different formats and convert to MM/DD/YYYY string
    IIF( REG_MATCH(TRANSACTION_DATE, '^\d{4}-\d{2}-\d{2}$'),
        TO_CHAR( TO_DATE(TRANSACTION_DATE,'YYYY-MM-DD'), 'MM/DD/YYYY' ),
    IIF( REG_MATCH(TRANSACTION_DATE, '^\d{2}/\d{2}/\d{4}$'),
        TRANSACTION_DATE,
    IIF( REG_MATCH(TRANSACTION_DATE, '^\d{2}-\d{2}-\d{4}$'),
        TO_CHAR( TO_DATE(TRANSACTION_DATE,'MM-DD-YYYY'), 'MM/DD/YYYY' ),
        TRANSACTION_DATE -- leave unknown format as-is; it'll be flagged invalid
    )))

    IS_VALID formula (1 = keep, 0 = reject)

    IIF(
      ISNULL(STORE_ID) OR
      ISNULL(PRODUCT_ID) OR
      ISNULL(UNIT_PRICE) OR
      QUANTITY = 0 OR
      DISC_CLEAN > 100,
    0, 1)

    REJECTION_REASON formula

    IIF( ISNULL(STORE_ID), 'Missing STORE_ID',
    IIF( ISNULL(PRODUCT_ID), 'Missing PRODUCT_ID',
    IIF( ISNULL(UNIT_PRICE), 'Missing UNIT_PRICE',
    IIF( QUANTITY = 0, 'Zero QUANTITY',
    IIF( DISC_CLEAN > 100, 'Discount exceeds 100%',
    'VALID')))))
  4. Add Router Transformation — RTR_VALID_REJECT
    • Drag Router onto canvas, connect from EXP_CLEANSE
    • Name: RTR_VALID_REJECT
    • Create two groups:
    Group NameCondition
    GRP_VALIDIS_VALID = 1
    GRP_REJECTIS_VALID = 0
    The Router's Default group catches anything not matched — you can connect it to the reject target as a safety net.
  5. Add Lookup — LKP_PRODUCT (for valid records only)
    • Drag Lookup transformation, connect from RTR_VALID_REJECT.GRP_VALID
    • Name: LKP_PRODUCT
    • Lookup Source: product_master.csv (via SRC_FLATFILE connection)
    • Lookup Condition: PRODUCT_ID = PRODUCT_ID
    • Return fields: PRODUCT_NAME, CATEGORY, BRAND
    • Multiple Match: Return First Row
  6. Add Lookup — LKP_STORE
    • Connect from LKP_PRODUCT output
    • Lookup Source: store_master.csv
    • Lookup Condition: STORE_ID = STORE_ID
    • Return fields: STORE_NAME, CITY, STATE
    • If lookup fails (no matching store) → record should be rejected. Add filter or handle in next Expression.
    Handling unmatched lookups: Create an EXP after LKP_STORE that checks: IIF(ISNULL(STORE_NAME), 0, 1) as STORE_FOUND — then add a Router or Filter to discard records where STORE_FOUND=0 into the reject file.
  7. Add Expression — EXP_CALC (compute KPI fields)
    • Connect from LKP_STORE valid output
    • Add calculated fields:
    GROSS_AMOUNT = UNIT_PRICE * QTY_CLEAN
    DISCOUNT_VALUE = GROSS_AMOUNT * (DISC_CLEAN / 100)
    NET_REVENUE = GROSS_AMOUNT - DISCOUNT_VALUE
  8. Add Source 2 — Clean Transactions (for Union)
    • Drag another Source transformation
    • Source Object: sales_transactions.csv
    • Also run this through LKP_PRODUCT and LKP_STORE lookups and EXP_CALC (or duplicate the lookups)
    In IICS you can re-use the same Lookup transformation. Connect both pipeline branches (dirty-valid and clean) to the same Lookup transformations by creating a second lookup instance or using a Union before the lookups.
  9. Add Union Transformation — UNI_MERGE
    • Drag Union onto canvas
    • Connect: Branch 1 = cleaned dirty valid records; Branch 2 = clean transaction records (post-lookup)
    • Map matching columns (TRANSACTION_ID, DATE_CLEAN, STORE_ID, STORE_NAME, CITY, STATE, PRODUCT_ID, PRODUCT_NAME, CATEGORY, BRAND, QTY_CLEAN, UNIT_PRICE, DISC_CLEAN, GROSS_AMOUNT, DISCOUNT_VALUE, NET_REVENUE)
  10. Add Target 1 — TGT_CLEAN_SALES.csv
    • Drag Target transformation, connect from Union output
    • Connection: TGT_FLATFILE
    • Target Object: create new → name TGT_CLEAN_SALES.csv
    • Map all fields from Union to target

    Output Columns for TGT_CLEAN_SALES.csv

    ColumnSource Field
    TRANSACTION_IDTRANSACTION_ID
    TRANSACTION_DATEDATE_CLEAN
    STORE_IDSTORE_ID
    STORE_NAMESTORE_NAME (from lookup)
    CITYCITY (from lookup)
    STATESTATE (from lookup)
    PRODUCT_IDPRODUCT_ID
    PRODUCT_NAMEPRODUCT_NAME (from lookup)
    CATEGORYCATEGORY (from lookup)
    BRANDBRAND (from lookup)
    QUANTITYQTY_CLEAN
    UNIT_PRICEUNIT_PRICE
    DISCOUNT_PERCENTDISC_CLEAN
    GROSS_AMOUNTGROSS_AMOUNT
    DISCOUNT_VALUEDISCOUNT_VALUE
    NET_REVENUENET_REVENUE
  11. Add Expression — EXP_REJECT_REASON (for rejected records)
    • Connect from RTR_VALID_REJECT.GRP_REJECT
    • Keep only essential columns: TRANSACTION_ID, TRANSACTION_DATE, STORE_ID, PRODUCT_ID, QUANTITY, DISCOUNT_PERCENT, REJECTION_REASON
  12. Add Target 2 — TGT_REJECTED_SALES.csv
    • Drag another Target transformation
    • Connection: TGT_FLATFILE
    • Target Object: TGT_REJECTED_SALES.csv
    • Map: TRANSACTION_ID, TRANSACTION_DATE, STORE_ID, PRODUCT_ID, QUANTITY, DISCOUNT_PERCENT, REJECTION_REASON
  13. Save and Run the Mapping
    • Click Save → Click Run
    • OR go to New > Mapping Task, attach this mapping, and run the task
    • Check All Jobs for status and row counts
    • Verify TGT_CLEAN_SALES.csv and TGT_REJECTED_SALES.csv in your Output folder
TASK 3 TGT_CATEGORY_SUMMARY.csv — Category-wise Monthly Sales Summary
Goal: For each CATEGORY + Month combination, compute TOTAL_TRANSACTIONS, TOTAL_QUANTITY, and TOTAL_REVENUE (sum of NET_REVENUE).

Pipeline Flow

SRC: TGT_CLEAN_SALES.csv
→
EXP_EXTRACT_MONTH
→
AGG_CATEGORY (Aggregator)
→
TGT_CATEGORY_SUMMARY.csv
  1. Create Mapping: M_CATEGORY_SUMMARY
    • Data Integration → New → Mapping → Name: M_CATEGORY_SUMMARY
  2. Add Source — TGT_CLEAN_SALES.csv
    • Connection: TGT_FLATFILE (since this is now our clean source)
    • Source Object: TGT_CLEAN_SALES.csv (the file produced by Task 1)
  3. Add Expression — EXP_EXTRACT_MONTH
    • Extract Year and Month from TRANSACTION_DATE
    YEAR = TO_INTEGER( SUBSTR(TRANSACTION_DATE, 7, 4) ) -- for MM/DD/YYYY
    MONTH = TO_INTEGER( SUBSTR(TRANSACTION_DATE, 1, 2) )
    Alternatively use: TO_CHAR(TO_DATE(TRANSACTION_DATE,'MM/DD/YYYY'),'YYYY') and TO_CHAR(TO_DATE(TRANSACTION_DATE,'MM/DD/YYYY'),'MM')
  4. Add Aggregator — AGG_CATEGORY
    • Drag Aggregator transformation, connect from EXP_EXTRACT_MONTH
    • Set Group By: YEAR, MONTH, CATEGORY
    • Add aggregate output fields:
    Output FieldAggregate Expression
    TOTAL_TRANSACTIONSCOUNT(TRANSACTION_ID)
    TOTAL_QUANTITYSUM(QUANTITY)
    TOTAL_REVENUESUM(NET_REVENUE)
  5. Add Target — TGT_CATEGORY_SUMMARY.csv
    • Map: MONTH, CATEGORY, TOTAL_TRANSACTIONS, TOTAL_QUANTITY, TOTAL_REVENUE
    • Target file: TGT_CATEGORY_SUMMARY.csv
  6. Save and Run
    • Create a Mapping Task, assign M_CATEGORY_SUMMARY mapping, and run
TASK 4 TGT_TOP_3_PRODUCTS_MONTHLY.csv — Top 3 Products per Month
Goal: For each YEAR + MONTH, find the Top 3 products by total QUANTITY sold. Exclude products with zero sales.

Pipeline Flow

SRC: TGT_CLEAN_SALES.csv
→
EXP_MONTH
→
AGG by Month+Product
→
SRT Sort
→
EXP_RANK (window function)
→
Filter RANK <= 3
→
TGT_TOP_3_PRODUCTS_MONTHLY.csv
  1. Create Mapping: M_TOP3_PRODUCTS_MONTHLY
  2. Add Source → EXP_MONTH (extract YEAR, MONTH)
    • Same formula as Task 3
  3. Add Aggregator — AGG_PRODUCT_MONTHLY
    • Group By: YEAR, MONTH, PRODUCT_ID, PRODUCT_NAME
    • Aggregates:
    FieldExpression
    TOTAL_QUANTITYSUM(QUANTITY)
    TOTAL_REVENUESUM(NET_REVENUE)
  4. Add Filter — Only products with TOTAL_QUANTITY > 0
    • Condition: TOTAL_QUANTITY > 0
  5. Add Sorter — SRT_BY_QTY
    • Sort by: YEAR ASC, MONTH ASC, TOTAL_QUANTITY DESC
    • This orders products within each month so highest quantity comes first
  6. Add Expression — EXP_RANK (compute rank within each month)
    IICS does not have a native RANK() window function in basic Mapping Designer. Use the following approach with running variables:
    -- Create 3 Variable ports in Expression:
    -- v_prev_month : stores previous MONTH value
    -- v_rank : stores current rank

    v_prev_month = IIF( MONTH = v_prev_month, v_prev_month, MONTH )
    v_rank = IIF( MONTH != v_prev_month, 1, v_rank + 1 )

    -- Output port:
    RANK_IN_MONTH = v_rank
    Alternative (recommended): Use IICS Advanced Mapping (Spark) which supports RANK() window function via SQL override or Python transformation. If using basic mapping, the variable port approach above works after an ORDER BY sort.
  7. Add Filter — RANK_IN_MONTH <= 3
    • Condition: RANK_IN_MONTH <= 3
  8. Add Target — TGT_TOP_3_PRODUCTS_MONTHLY.csv
    Column
    YEAR
    MONTH
    PRODUCT_ID
    PRODUCT_NAME
    TOTAL_QUANTITY
    TOTAL_REVENUE
    RANK

TASK 6 TGT_TOP_5_PRODUCTS_PER_STORE.csv — Top 5 Products per Store
Goal: For each STORE, rank the top 5 products by total quantity sold. RANK is within each store.
SRC: TGT_CLEAN_SALES.csv
→
AGG by STORE_ID + PRODUCT_ID
→
Sort (Store ASC, Qty DESC)
→
EXP_RANK per Store
→
Filter RANK <= 5
→
TGT_TOP_5_PRODUCTS_PER_STORE.csv
  1. Create Mapping: M_TOP5_PRODUCTS_PER_STORE
  2. Aggregator — AGG_STORE_PRODUCT
    • Group By: STORE_ID, STORE_NAME, PRODUCT_ID, PRODUCT_NAME

TASK 8 ★ COMPULSORY TGT_HIGH_VALUE_TRANSACTIONS.csv — High Value Transactions
Goal: Extract all transactions where NET_AMOUNT (per line item) is greater than the average NET_AMOUNT of that same month. Add a FLAG column.
NET_AMOUNT = (UNIT_PRICE × QUANTITY) − ((UNIT_PRICE × QUANTITY) × DISCOUNT_PERCENT / 100)
Challenge: Comparing each row to its month's average requires a self-join or lookup against a pre-computed monthly average. Two-pass approach is needed in IICS basic mapping.

Two-Pass Approach

Pass 1 — Compute Monthly Average (sub-mapping or first part of same mapping)

  1. Source: TGT_CLEAN_SALES.csv → EXP_NET_AMOUNT
    NET_AMOUNT = (UNIT_PRICE * QUANTITY) - ((UNIT_PRICE * QUANTITY) * DISCOUNT_PERCENT / 100)
  2. EXP_MONTH: extract YEAR, MONTH (same as before)
  3. Aggregator — AGG_MONTHLY_AVG
    • Group By: YEAR, MONTH
    • AVG_NET_AMOUNT = AVG(NET_AMOUNT)
    • Also keep COUNT and SUM if you want
  4. Write result to intermediate file: TMP_MONTHLY_AVG.csv (or use a Lookup cache)

Pass 2 — Flag High Value Transactions

  1. Source: TGT_CLEAN_SALES.csv → EXP_NET_AMOUNT → EXP_MONTH
  2. Lookup — LKP_MONTHLY_AVG
    • Lookup source: TMP_MONTHLY_AVG.csv
    • Lookup condition: YEAR = YEAR AND MONTH = MONTH
    • Return: AVG_NET_AMOUNT
  3. Expression — EXP_FLAG
    FLAG = IIF( NET_AMOUNT > AVG_NET_AMOUNT, 'HIGH_VALUE', 'NORMAL' )
  4. Filter — Keep only FLAG = 'HIGH_VALUE'
    • Condition: FLAG = 'HIGH_VALUE'
  5. Target — TGT_HIGH_VALUE_TRANSACTIONS.csv
    Column
    TRANSACTION_ID
    TRANSACTION_DATE
    STORE_NAME
    PRODUCT_NAME
    NET_AMOUNT
    FLAG
Tip for Advanced approach: In IICS with Spark / Advanced Mapping, you can do this in a single pass using a WINDOW transformation: AVG(NET_AMOUNT) OVER (PARTITION BY YEAR, MONTH) — no intermediate file needed.
3Create a Taskflow to Run All 8 Mappings in Sequence
A Taskflow in IICS chains multiple Mapping Tasks together, ensuring they execute in the correct dependency order.
  1. Create 8 Mapping Tasks
    • Data Integration → New → Mapping Task
    • Name each as: MT_CLEAN_DIRTY_SALES, MT_CATEGORY_SUMMARY, etc.
    • Assign the corresponding mapping to each task
    • Set Runtime Environment and save
  2. Create a New Taskflow
    • Data Integration → New → Taskflow
    • Name: TF_SALES_ETL_PIPELINE
  3. Design the Taskflow
    • Drag tasks from the palette onto the canvas in this order:
    START
    →
    MT_CLEAN_DIRTY_SALES (Tasks 1+2)
    →
    MT_CATEGORY_SUMMARY (Task 3)
    ↓
    MT_TOP3_PRODUCTS (Task 4)
    →
    MT_LOWEST_PRODUCT (Task 5)
    →
    MT_TOP5_PER_STORE (Task 6)
    ↓
    MT_STORE_LEADERBOARD (Task 7)
    →
    MT_HIGH_VALUE_TXN (Task 8)
    →
    END
    Tasks 3–7 all depend on Task 1's output (TGT_CLEAN_SALES.csv). Task 8 needs Task 1 first. Tasks 3–7 can run in parallel after Task 1 finishes.
  4. Add Conditions (On Success)
    • Connect each task with an On Success link so the next task only runs if the previous completed successfully
    • If any task fails, the taskflow can be configured to stop or skip
  5. Save and Run the Taskflow
    • Click Save → Click Run
    • Monitor under All Jobs — expand to see each task's status

Transformation Usage Summary

TransformationWhen to Use
SourceRead a CSV / database table
ExpressionDerive new fields, clean data, compute KPIs. Supports variable ports for running totals.
FilterKeep only rows matching a condition. Single output group.
RouterSplit data into multiple output groups (valid/reject, categories, etc.)
AggregatorGROUP BY + aggregate functions (SUM, COUNT, AVG, MAX, MIN)
SorterOrder rows — required before using variable-port rank logic
LookupEnrich a row by joining to a reference dataset (product/store master). Runs as cached lookup by default.
UnionCombine rows from multiple pipelines (UNION ALL equivalent)
JoinerJOIN two pipelines on a key (like SQL JOIN — use when Lookup is not sufficient)
TargetWrite output to CSV / database table
