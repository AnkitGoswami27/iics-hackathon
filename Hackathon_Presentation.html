What We're Solving

The Business Problem

  • A retail company collects daily sales data from multiple flat files — no automation existed
  • Raw data had missing values, duplicates, and inconsistent formats — analysts cleaned in Excel manually
  • Business metrics like net revenue were calculated differently by different people — no single source of truth
  • No central query-able table — a simple sales report took days of manual preparation

Our Solution

  • Automated pipeline using IICS CDI — from raw CSV to clean Oracle tables, zero manual intervention
  • Data quality layer built into the pipeline — bad rows are logged, not silently dropped
  • PL/SQL layer enforces business rules — KPIs calculated once, consistently, on every run
  • Clean star schema in Oracle XE — any BI tool can connect and query immediately

Expression Transformation – Key Logic

Every output field handles messy CSV data before hitting Oracle. Pattern: validate → convert → default. 

-- Safe numeric conversion
-- CSV columns can have blanks or text
IIF(IS_NUMBER(DISCOUNT_PERCENT),
    TO_DECIMAL(DISCOUNT_PERCENT, 2),
    0)

-- Gross sales derived inline
-- NOT a separate port (IICS rule:
-- output ports can't reference other
-- output ports, only input ports)
TO_DECIMAL(QUANTITY, 0) *
TO_DECIMAL(UNIT_PRICE, 2)

-- Month extraction
-- MONTH() does NOT exist in IICS
GET_DATE_PART(
    TO_DATE(ORDER_DATE, 'YYYY-MM-DD'),
    'MM')

-- Safe annual income
IIF(IS_NUMBER(ANNUAL_INCOME),
    TO_DECIMAL(ANNUAL_INCOME, 2),
    0)

IICS Expression Rule

An output port can only reference input ports from the same transformation — never another output port. Always inline your formula; do not split a derivation across multiple output ports.

Data Quality & Validation

Checks Applied in Pipeline

  • NULL / blank CUSTOMER_ID — primary key cannot be empty; Filter drops these before target
  • Non-numeric values in ANNUAL_INCOME, LOYALTY_POINTS — IS_NUMBER wrapper prevents conversion errors
  • Invalid date formats in ORDER_DATE — TO_DATE will throw; router catches and logs the row
  • Duplicate CUSTOMER_IDs — Pre SQL DELETE ensures no unique constraint violations
  • Negative QUANTITY or DISCOUNT_PERCENT > 100 — Filter condition blocks these out-of-range values

REJECTED_RECORDS Table

  • Router “Default” group sends invalid rows here
  • Every row tagged with a REJECTION_REASON column
  • Ops team can review and reprocess without rerunning the full pipeline

PL/SQL – Business Logic Layer

Incremental Load Procedure (MERGE)

CREATE OR REPLACE PROCEDURE
    usp_load_fact_sales(
        p_batch_date IN DATE := SYSDATE)
AS
    v_rows  NUMBER := 0;
BEGIN
    MERGE INTO FACT_SALES tgt
    USING FACT_SALES_STAGE src
        ON (tgt.SALE_ID = src.SALE_ID)
    WHEN MATCHED THEN UPDATE SET
        tgt.NET_REVENUE = src.QUANTITY *
            src.UNIT_PRICE *
            (1 - src.DISCOUNT_PERCENT/100)
    WHEN NOT MATCHED THEN INSERT
        VALUES (src.SALE_ID, src.CUSTOMER_ID,
                src.PRODUCT_ID, src.ORDER_ID,
                src.QUANTITY, src.UNIT_PRICE,
                src.DISCOUNT_PERCENT,
                src.QUANTITY * src.UNIT_PRICE *
                (1 - src.DISCOUNT_PERCENT/100),
                EXTRACT(MONTH FROM src.SALE_DATE));
    v_rows := SQL%ROWCOUNT;
    DBMS_OUTPUT.PUT_LINE(
        'Rows merged: ' || v_rows);
END;

Why Each Part Exists

  • MERGE — handles new rows (INSERT) and changed rows (UPDATE) in a single statement — no double-scanning the source
  • NET_REVENUE in PL/SQL — formula lives in one place; not in the CSV, not in IICS — single source of truth for business logic
  • EXTRACT(MONTH) — populates SALE_MONTH for partition-based queries without an extra ETL step
  • SQL%ROWCOUNT — tells us exactly how many rows were affected; written to ETL audit log table

Taskflow – Pipeline Orchestration

  • What is a Taskflow? — IICS object that chains multiple mappings into a single scheduled, sequenced job — like a workflow DAG
  • Why load order matters — DIM tables must load before FACT_SALES or Oracle throws FK constraint errors; Taskflow enforces this automatically
  • Fail-fast design — if any DIM load fails, all downstream mappings stop; prevents half-loaded dirty data entering the gold layer
  • Daily scheduling — IICS built-in Scheduler triggers the full taskflow; no external cron job or batch script needed
  • PL/SQL Command Task — runs EXEC usp_load_fact_sales after all IICS mappings complete; keeps business logic in Oracle, not in IICS

Challenges We Actually Hit

Not textbook problems — these came up while actually building the mappings. Each one was a real learning moment.

TO_DECIMAL() throwing “too many operands”
Thought it worked like Oracle's ROUND with 3 arguments (value, precision, scale). IICS only takes 2. Fix: TO_DECIMAL(col, 2) — second arg is scale only.
MONTH() function not recognized in Expression
IICS date functions are not the same as Oracle SQL. Switched to GET_DATE_PART(TO_DATE(col,'YYYY-MM-DD'), 'MM') — exact equivalent that actually works in IICS.
ORA-00001 unique constraint violated on Upsert
The built-in Update Columns key config was wrong — CUSTOMER_ID was on the wrong side. Simpler fix: Pre SQL = DELETE FROM DIM_CUSTOMERS, Operation = Insert. Clean and reliable.
Output port trying to reference another output port
IICS Expression only allows output ports to reference input ports — not each other. Had to inline the GROSS_SALES formula instead of reusing it from a separate port.
Aggregator: “invalid symbol reference” for NET_SALES
Was pointing to a derived output port from Expression. Fix: reference the upstream input field directly. Used AVG(o_NET_REVENUE) mapped to the input, not the Expression output.
Aggregator error — sorting missing upstream
IICS Aggregator requires data pre-sorted on the group-by key. Added a Sorter transformation before the Aggregator — error was gone immediately.
