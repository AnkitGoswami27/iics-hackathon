PART 1 — DATABASE FUNDAMENTALS

1. Entity Relationship Diagram (ERD)

What is it?

A visual blueprint showing Entities (tables), Attributes (columns), and Relationships (how tables connect). Created before writing any SQL — at the design stage.

ERD Components

SymbolMeaning
RectangleEntity (Table)
EllipseAttribute (Column)
DiamondRelationship between entities
Double RectangleWeak Entity (depends on another entity)
Underlined attributePrimary Key

Relationship Types

TypeMeaningExample
One-to-One1 row ↔ 1 rowEmployee ↔ Passport
One-to-Many1 row ↔ many rowsCustomer → Orders
Many-to-ManyMany ↔ ManyStudents ↔ Courses (needs bridge table)
Q: What is a weak entity?
A: An entity that cannot exist without another. e.g., ORDER_ITEM cannot exist without ORDER. Has a partial key, not a full primary key.

Q: Difference between ERD and schema?
A: ERD is logical/conceptual design. Schema is the actual physical implementation in the database.

2. Transaction Concepts

What is a Transaction?

A logical unit of work — all operations succeed together or none of them do.

ACID Properties

PropertyMeaningExample
AtomicityAll or nothingBank transfer: debit + credit both happen or neither
ConsistencyDB stays valid before and afterBalance never goes negative
IsolationTransactions don't interfereTwo users updating same row handled properly
DurabilityCommitted data survives crashesAfter COMMIT, data is permanent even after server restart

Transaction Commands

COMMIT;              -- Make changes permanent
ROLLBACK;            -- Undo all changes since last COMMIT
SAVEPOINT sp1;       -- Create a checkpoint
ROLLBACK TO sp1;     -- Undo only up to the savepoint
Q: What happens if you close SQL*Plus without COMMIT?
A: Oracle automatically issues a ROLLBACK — all uncommitted changes are lost.

Q: What is a dirty read?
A: Reading uncommitted data from another transaction. Oracle prevents this using MVCC (Multi-Version Concurrency Control).

Q: What is MVCC?
A: Multi-Version Concurrency Control — Oracle keeps a read-consistent snapshot of data for each query using UNDO segments, so readers don't block writers.

3. Normalization

What is it?

Organizing tables to reduce redundancy and improve data integrity by following a series of rules called Normal Forms.

1NF — First Normal Form

  • Each column has atomic (indivisible) values
  • No repeating groups or arrays in a column
-- BAD (not 1NF): Subjects = "Math, Science"
Student(ID, Name, Subjects)

-- GOOD (1NF): atomic values
Student(ID, Name) + StudentSubject(StudentID, Subject)

2NF — Second Normal Form

  • Must be in 1NF
  • No partial dependency — every non-key column depends on the WHOLE primary key
-- BAD: OrderItem(OrderID, ProductID, ProductName)
--      ProductName depends only on ProductID, not on (OrderID + ProductID)
-- GOOD: Separate Product(ProductID, ProductName) table

3NF — Third Normal Form

  • Must be in 2NF
  • No transitive dependency — non-key column should not depend on another non-key column
-- BAD: Employee(EmpID, DeptID, DeptName)
--      DeptName depends on DeptID (not directly on EmpID)
-- GOOD: Separate Department(DeptID, DeptName) table

BCNF — Boyce-Codd Normal Form

Stricter version of 3NF. Every determinant must be a candidate key.

Q: What is denormalization and when do you use it?
A: Intentionally adding redundancy for performance. Used in Data Warehouses where read speed is more important than write integrity.

Q: Can a table be in 3NF but not BCNF?
A: Yes — when there are multiple overlapping candidate keys.

4. Data Models

Relational Model

Data in tables (relations). Relationships via foreign keys. Uses standard SQL. Most common — Oracle, MySQL, PostgreSQL.

Object-Oriented Model

Data as objects (like OOP classes). Objects have attributes + methods. Supports inheritance, encapsulation. Example: db4o, ObjectDB.

OODBMS vs ORDBMS

FeatureOODBMSORDBMS
BasePure OOPRelational + OOP extensions
SQLNo standard SQLStandard SQL + extensions
Exampledb4oOracle, PostgreSQL
InheritanceFullPartial
-- Oracle ORDBMS: object type inside relational table
CREATE TYPE address_type AS OBJECT (
  street VARCHAR2(100),
  city   VARCHAR2(50)
);
CREATE TABLE employees (
  emp_id  NUMBER,
  address address_type   -- object inside relational table
);
Q: Why did OODBMS not replace RDBMS?
A: SQL is universally known, RDBMS is battle-tested for decades, and ACID compliance is harder to guarantee in OODBMS. RDBMS won enterprise adoption.

PART 2 — SQL

6. Basic SQL Statements

-- SELECT basic
SELECT column1, column2 FROM table_name;
SELECT * FROM employees;

-- Arithmetic
SELECT salary, salary * 12 AS annual_salary FROM employees;

-- DISTINCT
SELECT DISTINCT department_id FROM employees;

-- Concatenation
SELECT first_name || ' ' || last_name AS full_name FROM employees;
Q: What is the difference between WHERE and HAVING?
A: WHERE filters rows BEFORE grouping. HAVING filters groups AFTER GROUP BY.

Q: Can you use a column alias in WHERE clause?
A: No — aliases are resolved after WHERE. Use a subquery if needed.

Q: SQL clause execution order?
A: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

7. Restricting and Sorting Data

WHERE salary > 50000
WHERE department_id IN (10, 20, 30)
WHERE salary BETWEEN 30000 AND 60000
WHERE last_name LIKE 'S%'          -- starts with S
WHERE last_name LIKE '_ing'        -- second char onwards = ing
WHERE commission_pct IS NULL
WHERE commission_pct IS NOT NULL

-- ORDER BY
SELECT * FROM employees ORDER BY salary DESC;
SELECT * FROM employees ORDER BY department_id ASC, salary DESC;
SELECT * FROM employees ORDER BY commission_pct NULLS LAST;
Q: Difference between = and LIKE?
A: = is exact match. LIKE supports wildcards: % (any characters), _ (single character).

Q: What does NULLS LAST do?
A: Pushes NULL values to the end of the sorted result. Default in DESC order NULLs come first.

Q: Difference between ROUND and TRUNC?
A: ROUND rounds mathematically (≥5 rounds up). TRUNC simply cuts — no rounding.

Q: Difference between NVL and COALESCE?
A: NVL takes exactly 2 arguments. COALESCE takes multiple, returns first non-NULL. COALESCE is ANSI standard.

Q: What is DUAL?
A: A dummy one-row, one-column Oracle table used to test expressions or call functions without a real table.

9. Joins — Displaying Data from Multiple Tables

-- INNER JOIN — only matching rows
SELECT e.first_name, d.department_name
FROM employees e
INNER JOIN departments d ON e.department_id = d.department_id;

-- LEFT OUTER JOIN — all from left, NULLs where no match on right
SELECT e.first_name, d.department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.department_id;

-- RIGHT OUTER JOIN — all from right, NULLs where no match on left
SELECT e.first_name, d.department_name
FROM employees e
RIGHT JOIN departments d ON e.department_id = d.department_id;

-- FULL OUTER JOIN — all rows from both sides
SELECT e.first_name, d.department_name
FROM employees e
FULL OUTER JOIN departments d ON e.department_id = d.department_id;

-- CROSS JOIN — Cartesian product (every row × every row)
SELECT e.first_name, d.department_name
FROM employees e CROSS JOIN departments d;

-- SELF JOIN — table joining itself
SELECT e.first_name AS employee, m.first_name AS manager
FROM employees e
JOIN employees m ON e.manager_id = m.employee_id;

-- Oracle old syntax (+) for outer join
SELECT e.first_name, d.department_name
FROM employees e, departments d
WHERE e.department_id = d.department_id(+);  -- LEFT outer join
Q: What is a Cartesian product?
A: When two tables are joined WITHOUT a join condition. Every row in A pairs with every row in B. 10 × 10 = 100 rows.

Q: When would you use a SELF JOIN?
A: Hierarchical data — employee-manager relationship stored in the same table.

Q: Difference between INNER JOIN and EQUIJOIN?
A: EQUIJOIN uses = operator (a type of inner join). INNER JOIN is the broader category (also includes non-equal conditions).

10. SET Operators

-- UNION — combines results, removes duplicates (slower)
SELECT employee_id FROM employees
UNION
SELECT employee_id FROM retired_employees;

-- UNION ALL — combines results, KEEPS duplicates (faster)
SELECT employee_id FROM employees
UNION ALL
SELECT employee_id FROM retired_employees;

-- INTERSECT — only rows that appear in BOTH queries
SELECT employee_id FROM employees
INTERSECT
SELECT employee_id FROM managers;

-- MINUS — rows in first query but NOT in second
SELECT employee_id FROM employees
MINUS
SELECT employee_id FROM managers;

Rules for SET Operators

  • Same number of columns in both SELECT statements
  • Compatible data types column by column
  • Column names are taken from the FIRST query
  • ORDER BY only at the very end, on the final result
Q: Difference between UNION and UNION ALL?
A: UNION removes duplicates (sorts internally — slower). UNION ALL keeps duplicates (faster — no sort needed).

Q: When would you use MINUS?
A: Finding records in one table but not another — e.g., "customers who have NOT placed any order."

11. Aggregating Data

SELECT COUNT(*)                FROM employees;  -- counts all rows incl. NULLs
SELECT COUNT(commission_pct)   FROM employees;  -- ignores NULLs
SELECT SUM(salary)             FROM employees;
SELECT AVG(salary)             FROM employees;
SELECT MAX(salary)             FROM employees;
SELECT MIN(salary)             FROM employees;

-- GROUP BY
SELECT department_id, AVG(salary)
FROM employees
GROUP BY department_id;

-- HAVING — filter on groups (like WHERE but for groups)
SELECT department_id, AVG(salary)
FROM employees
GROUP BY department_id
HAVING AVG(salary) > 8000;

-- ROLLUP — subtotals per group + grand total
SELECT department_id, job_id, SUM(salary)
FROM employees
GROUP BY ROLLUP(department_id, job_id);

-- CUBE — all possible subtotal combinations
SELECT department_id, job_id, SUM(salary)
FROM employees
GROUP BY CUBE(department_id, job_id);
Q: Does COUNT(*) count NULLs?
A: COUNT(*) counts ALL rows including NULLs. COUNT(column) ignores NULLs.

Q: Can you use aggregate functions in WHERE?
A: No. Use HAVING. WHERE filters rows; HAVING filters groups after GROUP BY.

Q: Difference between ROLLUP and CUBE?
A: ROLLUP gives hierarchical subtotals (one direction). CUBE gives ALL possible combinations of subtotals.

12. Subqueries & Correlated Subqueries

-- Single-row subquery
SELECT first_name, salary FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);

-- Multi-row subquery with IN
SELECT first_name FROM employees
WHERE department_id IN (
  SELECT department_id FROM departments WHERE location_id = 1700
);

-- ANY — true if ANY value in subquery matches
SELECT salary FROM employees
WHERE salary > ANY (SELECT salary FROM employees WHERE department_id = 30);

-- ALL — true only if ALL values in subquery match
SELECT salary FROM employees
WHERE salary > ALL (SELECT salary FROM employees WHERE department_id = 30);

-- Inline view (subquery in FROM)
SELECT d.department_id, d.avg_sal
FROM (SELECT department_id, AVG(salary) avg_sal
      FROM employees GROUP BY department_id) d
WHERE d.avg_sal > 8000;

-- CORRELATED subquery — references outer query column
-- Find employees who earn more than their OWN department average
SELECT e1.first_name, e1.salary, e1.department_id
FROM employees e1
WHERE e1.salary > (
  SELECT AVG(e2.salary)
  FROM employees e2
  WHERE e2.department_id = e1.department_id  -- references outer query
);

-- EXISTS — stops at first match (faster than IN for large datasets)
SELECT first_name FROM employees e
WHERE EXISTS (
  SELECT 1 FROM departments d
  WHERE d.department_id = e.department_id AND d.location_id = 1700
);
Q: Difference between correlated and non-correlated subquery?
A: Non-correlated: runs ONCE, result reused for all outer rows. Correlated: runs ONCE PER ROW of outer query (references outer column).

Q: When to use EXISTS vs IN?
A: EXISTS is faster when subquery returns many rows (stops at first match). IN compares all values — fine for small result sets.

13. Manipulating Data — DML

-- INSERT
INSERT INTO employees (employee_id, first_name, salary, department_id)
VALUES (999, 'John', 50000, 10);

-- INSERT with subquery
INSERT INTO emp_backup SELECT * FROM employees WHERE department_id = 10;

-- UPDATE
UPDATE employees SET salary = salary * 1.10 WHERE department_id = 20;

-- DELETE
DELETE FROM employees WHERE employee_id = 999;

-- MERGE (Upsert — insert if not exists, update if exists)
MERGE INTO employees tgt
USING new_employees src ON (tgt.employee_id = src.employee_id)
WHEN MATCHED THEN
  UPDATE SET tgt.salary = src.salary
WHEN NOT MATCHED THEN
  INSERT (employee_id, first_name, salary)
  VALUES (src.employee_id, src.first_name, src.salary);

14. Creating, Managing and Partitioning Tables

-- CREATE TABLE
CREATE TABLE products (
  product_id   NUMBER(6)      PRIMARY KEY,
  product_name VARCHAR2(100)  NOT NULL,
  price        NUMBER(10,2),
  created_date DATE DEFAULT SYSDATE
);

-- ALTER TABLE
ALTER TABLE products ADD (discount NUMBER(5,2));
ALTER TABLE products MODIFY (product_name VARCHAR2(200));
ALTER TABLE products DROP COLUMN discount;
ALTER TABLE products RENAME TO inventory;
DROP TABLE inventory;
DROP TABLE inventory PURGE;  -- bypass recycle bin

-- RANGE Partitioning (most common in DWH)
CREATE TABLE sales (
  sale_id   NUMBER,
  sale_date DATE,
  amount    NUMBER
)
PARTITION BY RANGE (sale_date) (
  PARTITION p_2024   VALUES LESS THAN (DATE'2025-01-01'),
  PARTITION p_2025   VALUES LESS THAN (DATE'2026-01-01'),
  PARTITION p_future VALUES LESS THAN (MAXVALUE)
);

-- LIST Partitioning
CREATE TABLE emp_part
PARTITION BY LIST (department_id) (
  PARTITION p_admin   VALUES (10, 20),
  PARTITION p_finance VALUES (30, 40),
  PARTITION p_other   VALUES (DEFAULT)
);

-- HASH Partitioning — Oracle distributes rows evenly
CREATE TABLE orders_part
PARTITION BY HASH (order_id)
PARTITIONS 4;
Q: Why use partitioning?
A: Partition pruning — queries scan ONLY relevant partitions, not the full table. Dramatically improves performance on large datasets.

Q: What is partition pruning?
A: When the WHERE clause matches the partition key, Oracle automatically skips all other partitions.

15. Including Constraints

CREATE TABLE employees (
  employee_id   NUMBER(6)    CONSTRAINT emp_pk PRIMARY KEY,
  first_name    VARCHAR2(50) CONSTRAINT emp_fname_nn NOT NULL,
  email         VARCHAR2(100) CONSTRAINT emp_email_uq UNIQUE,
  salary        NUMBER(10,2) CONSTRAINT emp_sal_ck CHECK (salary > 0),
  department_id NUMBER(4)    CONSTRAINT emp_dept_fk
                             REFERENCES departments(department_id)
);

-- Add after table creation
ALTER TABLE employees ADD CONSTRAINT emp_sal_ck CHECK (salary > 0);

-- Disable / Enable constraint
ALTER TABLE employees DISABLE CONSTRAINT emp_dept_fk;
ALTER TABLE employees ENABLE  CONSTRAINT emp_dept_fk;

-- FK with cascade options
REFERENCES departments(department_id) ON DELETE CASCADE   -- delete child too
REFERENCES departments(department_id) ON DELETE SET NULL  -- set FK to NULL
Q: Difference between UNIQUE and PRIMARY KEY?
A: PRIMARY KEY = UNIQUE + NOT NULL. A table can have only ONE primary key but MULTIPLE unique constraints. UNIQUE allows NULLs.

Q: What is a composite primary key?
A: A primary key made of multiple columns. The COMBINATION must be unique, not individual columns.

16. Creating Views

-- CREATE VIEW
CREATE VIEW emp_dept_view AS
SELECT e.first_name, e.salary, d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id
WHERE e.salary > 5000;

-- WITH CHECK OPTION — prevents DML that violates the WHERE
CREATE VIEW high_sal_view AS
SELECT * FROM employees WHERE salary > 10000
WITH CHECK OPTION;

-- WITH READ ONLY — no DML through this view
CREATE VIEW emp_readonly AS
SELECT * FROM employees WITH READ ONLY;

-- FORCE VIEW — creates even if base table doesn't exist yet
CREATE FORCE VIEW future_view AS
SELECT * FROM future_table;
Q: Can you perform DML on a view?
A: Yes, IF based on a single table and doesn't use GROUP BY, DISTINCT, aggregate functions, or ROWNUM.

Q: What is a materialized view?
A: A view whose result is physically stored (like a snapshot table). Refreshed periodically. Used in DWH for performance.

17. Creating Sequences

CREATE SEQUENCE emp_seq
  START WITH 1000
  INCREMENT BY 1
  MAXVALUE 9999999
  NOCYCLE
  CACHE 20;

-- Usage
INSERT INTO employees (employee_id, first_name)
VALUES (emp_seq.NEXTVAL, 'John');

SELECT emp_seq.CURRVAL FROM dual;  -- current value (same session only)
ALTER SEQUENCE emp_seq INCREMENT BY 5;
DROP SEQUENCE emp_seq;
Q: Can a sequence guarantee no gaps?
A: No — if a transaction rolls back, the sequence value is lost. Sequences are non-transactional.

Q: What is CACHE in sequence?
A: Oracle pre-allocates N values in memory for fast generation. On instance crash, cached values are lost, causing gaps.

18. Synonyms

CREATE PUBLIC SYNONYM emp FOR hr.employees;  -- all users can access
CREATE SYNONYM emp FOR hr.employees;          -- current user only

SELECT * FROM emp;   -- transparently accesses hr.employees

DROP SYNONYM emp;
DROP PUBLIC SYNONYM emp;

Why use Synonyms? Hide schema names. If underlying table moves, only update the synonym — applications don't change. Adds a security layer.

19. Indexes

-- B-Tree Index (default) — high cardinality columns
CREATE INDEX emp_name_idx ON employees(last_name);

-- Composite index
CREATE INDEX emp_dept_sal ON employees(department_id, salary);

-- Unique index
CREATE UNIQUE INDEX emp_email_idx ON employees(email);

-- Bitmap index — low cardinality (gender, status, yes/no)
CREATE BITMAP INDEX emp_gender_idx ON employees(gender);

-- Function-based index
CREATE INDEX emp_upper_name ON employees(UPPER(last_name));
-- Now this uses the index:
SELECT * FROM employees WHERE UPPER(last_name) = 'KING';

DROP INDEX emp_name_idx;
Q: When does Oracle NOT use an index?
A: Function applied to indexed column without function-based index; full table scan is cheaper (small tables); low cardinality with B-tree index.

Q: Difference between B-Tree and Bitmap index?
A: B-Tree: best for high cardinality (unique/near-unique). Bitmap: best for low cardinality (M/F, Y/N). Bitmap terrible for OLTP (row locking), great for DWH.

20. Controlling User Access — DCL

CREATE USER analyst IDENTIFIED BY Password123;
GRANT CREATE SESSION TO analyst;
GRANT CREATE TABLE  TO analyst;
GRANT SELECT, INSERT ON employees TO analyst;
GRANT SELECT ON employees TO analyst WITH GRANT OPTION;
REVOKE SELECT ON employees FROM analyst;

-- Roles
CREATE ROLE hr_role;
GRANT SELECT ON employees TO hr_role;
GRANT hr_role TO analyst;
Q: Difference between WITH ADMIN OPTION and WITH GRANT OPTION?
A: ADMIN OPTION: for system privileges — recipient can grant to others; revoke does NOT cascade. GRANT OPTION: for object privileges — revoke DOES cascade to all grantor's grantees.
PART 3 — PL/SQL

21. Introduction to PL/SQL

What is PL/SQL?

Procedural Language extension to SQL — adds programming constructs (loops, conditions, variables, error handling) to SQL. Entire block sent to DB at once for better performance.

Block Structure

DECLARE
  -- Variable declarations (optional)
  v_name VARCHAR2(50);
  v_sal  NUMBER := 0;
BEGIN
  -- Executable statements (mandatory)
  SELECT first_name INTO v_name
  FROM employees WHERE employee_id = 100;
  DBMS_OUTPUT.PUT_LINE('Name: ' || v_name);
EXCEPTION
  -- Error handling (optional)
  WHEN NO_DATA_FOUND THEN
    DBMS_OUTPUT.PUT_LINE('Employee not found');
END;
/

22. Declaring Variables

DECLARE
  v_name    VARCHAR2(50);
  v_salary  NUMBER(10,2) := 50000;
  v_date    DATE         := SYSDATE;
  v_flag    BOOLEAN      := TRUE;
  c_tax     CONSTANT NUMBER := 0.18;  -- constant

  -- %TYPE — inherits column's datatype automatically
  v_emp_name employees.first_name%TYPE;
  v_emp_sal  employees.salary%TYPE;

  -- %ROWTYPE — inherits entire row structure
  v_emp_rec  employees%ROWTYPE;
BEGIN
  -- SELECT INTO for single row
  SELECT first_name, salary INTO v_emp_name, v_emp_sal
  FROM employees WHERE employee_id = 100;

  -- %ROWTYPE usage
  SELECT * INTO v_emp_rec FROM employees WHERE employee_id = 100;
  DBMS_OUTPUT.PUT_LINE(v_emp_rec.first_name || ' - ' || v_emp_rec.salary);
END;
/
Q: Why use %TYPE instead of hardcoding the datatype?
A: If the column type changes (e.g., salary from NUMBER(8) to NUMBER(10,2)), %TYPE automatically picks up the new type. Hardcoded type would break silently or cause runtime errors.

23. Control Statements

-- IF-ELSIF-ELSE
IF v_salary > 100000 THEN
  v_grade := 'A';
ELSIF v_salary > 50000 THEN
  v_grade := 'B';
ELSE
  v_grade := 'C';
END IF;

-- CASE
v_result := CASE v_dept_id
              WHEN 10 THEN 'Admin'
              WHEN 20 THEN 'HR'
              ELSE 'Other'
            END;

-- Basic LOOP
LOOP
  v_count := v_count + 1;
  EXIT WHEN v_count >= 10;
END LOOP;

-- WHILE LOOP
WHILE v_count < 10 LOOP
  v_count := v_count + 1;
END LOOP;

-- FOR LOOP (automatically manages counter)
FOR i IN 1..10 LOOP
  DBMS_OUTPUT.PUT_LINE('Count: ' || i);
END LOOP;

-- REVERSE FOR LOOP
FOR i IN REVERSE 1..10 LOOP
  DBMS_OUTPUT.PUT_LINE(i);  -- prints 10, 9, 8 ... 1
END LOOP;

24. Composite Datatypes

-- PL/SQL Record
DECLARE
  TYPE emp_rec_type IS RECORD (
    emp_id   NUMBER,
    emp_name VARCHAR2(50),
    salary   NUMBER
  );
  v_emp emp_rec_type;
BEGIN
  v_emp.emp_id := 101;  v_emp.emp_name := 'John';  v_emp.salary := 60000;
END;

-- Associative Array (Index-By Table)
DECLARE
  TYPE salary_table IS TABLE OF NUMBER INDEX BY PLS_INTEGER;
  v_salaries salary_table;
BEGIN
  v_salaries(1) := 50000;
  v_salaries(2) := 75000;
  DBMS_OUTPUT.PUT_LINE(v_salaries(1));
END;

-- Nested Table (no size limit)
DECLARE
  TYPE name_list IS TABLE OF VARCHAR2(50);
  v_names name_list := name_list('Alice', 'Bob', 'Charlie');
BEGIN
  FOR i IN 1..v_names.COUNT LOOP
    DBMS_OUTPUT.PUT_LINE(v_names(i));
  END LOOP;
END;

-- VARRAY (fixed maximum size)
DECLARE
  TYPE month_array IS VARRAY(12) OF VARCHAR2(10);
  v_months month_array := month_array('Jan','Feb','Mar');
END;
Q: Difference between Nested Table and VARRAY?
A: VARRAY has a fixed maximum size and preserves element order. Nested Table has no size limit and doesn't guarantee order when stored in DB. Nested table allows DELETE of individual elements; VARRAY doesn't.

25. Cursors

Implicit Cursor

Oracle automatically creates for every DML and single-row SELECT INTO statement.

UPDATE employees SET salary = salary * 1.1 WHERE department_id = 10;
IF SQL%ROWCOUNT > 0 THEN
  DBMS_OUTPUT.PUT_LINE(SQL%ROWCOUNT || ' rows updated');
END IF;
-- Attributes: SQL%FOUND, SQL%NOTFOUND, SQL%ROWCOUNT, SQL%ISOPEN

Explicit Cursor — Basic Pattern

DECLARE
  CURSOR emp_cursor IS
    SELECT first_name, salary FROM employees WHERE department_id = 10;
  v_name employees.first_name%TYPE;
  v_sal  employees.salary%TYPE;
BEGIN
  OPEN emp_cursor;
  LOOP
    FETCH emp_cursor INTO v_name, v_sal;
    EXIT WHEN emp_cursor%NOTFOUND;
    DBMS_OUTPUT.PUT_LINE(v_name || ' - ' || v_sal);
  END LOOP;
  CLOSE emp_cursor;
END;
/

Cursor FOR LOOP (Best Practice — auto open/fetch/close)

BEGIN
  FOR rec IN (SELECT first_name, salary FROM employees WHERE department_id = 10)
  LOOP
    DBMS_OUTPUT.PUT_LINE(rec.first_name || ' - ' || rec.salary);
  END LOOP;
END;
/

26. Advanced Explicit Cursor Concepts

-- Cursor with Parameters
DECLARE
  CURSOR emp_cursor(p_dept_id NUMBER) IS
    SELECT first_name, salary FROM employees WHERE department_id = p_dept_id;
BEGIN
  FOR rec IN emp_cursor(10) LOOP DBMS_OUTPUT.PUT_LINE(rec.first_name); END LOOP;
  FOR rec IN emp_cursor(20) LOOP DBMS_OUTPUT.PUT_LINE(rec.first_name); END LOOP;
END;

-- FOR UPDATE cursor (lock the rows)
DECLARE
  CURSOR sal_cursor IS
    SELECT employee_id, salary FROM employees
    WHERE department_id = 10 FOR UPDATE OF salary;
BEGIN
  FOR rec IN sal_cursor LOOP
    UPDATE employees SET salary = rec.salary * 1.1
    WHERE CURRENT OF sal_cursor;   -- updates the row cursor is ON
  END LOOP;
  COMMIT;
END;
Q: What is WHERE CURRENT OF?
A: Updates/deletes the exact row the cursor is currently positioned on. Requires FOR UPDATE clause on the cursor.

Q: Cursor attributes summary?
A: %FOUND (last fetch got a row), %NOTFOUND (last fetch got nothing), %ROWCOUNT (rows fetched so far), %ISOPEN (cursor is open).

27. Exception Handling

DECLARE
  v_salary employees.salary%TYPE;
BEGIN
  SELECT salary INTO v_salary FROM employees WHERE employee_id = 9999;

EXCEPTION
  WHEN NO_DATA_FOUND    THEN DBMS_OUTPUT.PUT_LINE('Not found');
  WHEN TOO_MANY_ROWS    THEN DBMS_OUTPUT.PUT_LINE('Multiple rows returned');
  WHEN ZERO_DIVIDE      THEN DBMS_OUTPUT.PUT_LINE('Division by zero');
  WHEN OTHERS           THEN
    DBMS_OUTPUT.PUT_LINE('Error: ' || SQLERRM);
    DBMS_OUTPUT.PUT_LINE('Code: ' || SQLCODE);
END;

-- User-defined exception
DECLARE
  e_invalid_salary EXCEPTION;
  v_sal NUMBER := -100;
BEGIN
  IF v_sal < 0 THEN RAISE e_invalid_salary; END IF;
EXCEPTION
  WHEN e_invalid_salary THEN DBMS_OUTPUT.PUT_LINE('Salary cannot be negative');
END;

-- RAISE_APPLICATION_ERROR (custom error code + message)
IF v_sal < 0 THEN
  RAISE_APPLICATION_ERROR(-20001, 'Salary cannot be negative');
END IF;
Q: Range for user-defined errors?
A: -20000 to -20999 — reserved for RAISE_APPLICATION_ERROR.

Q: What are SQLERRM and SQLCODE?
A: SQLCODE: error number (negative for Oracle errors, 0 for success, +100 for NO_DATA_FOUND). SQLERRM: full error message text.

28. Creating Procedures

CREATE OR REPLACE PROCEDURE update_salary (
  p_emp_id  IN  NUMBER,
  p_percent IN  NUMBER,
  p_new_sal OUT NUMBER
)
IS
  v_old_sal employees.salary%TYPE;
BEGIN
  SELECT salary INTO v_old_sal FROM employees WHERE employee_id = p_emp_id;
  p_new_sal := v_old_sal * (1 + p_percent/100);
  UPDATE employees SET salary = p_new_sal WHERE employee_id = p_emp_id;
  COMMIT;
EXCEPTION
  WHEN NO_DATA_FOUND THEN
    RAISE_APPLICATION_ERROR(-20001, 'Employee not found: ' || p_emp_id);
END update_salary;
/

-- Calling the procedure
DECLARE
  v_new_salary NUMBER;
BEGIN
  update_salary(101, 10, v_new_salary);
  DBMS_OUTPUT.PUT_LINE('New salary: ' || v_new_salary);
END;
/

A: Function MUST return a value via RETURN and CAN be used in SQL SELECT/WHERE. Procedure uses OUT parameters and CANNOT be used directly in SQL.

29. Creating Functions

CREATE OR REPLACE FUNCTION get_annual_salary (
  p_emp_id IN NUMBER
) RETURN NUMBER
IS
  v_salary employees.salary%TYPE;
BEGIN
  SELECT salary INTO v_salary FROM employees WHERE employee_id = p_emp_id;
  RETURN v_salary * 12;
EXCEPTION
  WHEN NO_DATA_FOUND THEN RETURN NULL;
END get_annual_salary;
/

-- KEY ADVANTAGE: usable directly in SQL
SELECT first_name, get_annual_salary(employee_id) AS annual_sal
FROM employees;

-- Also usable in PL/SQL
DECLARE v_annual NUMBER;
BEGIN
  v_annual := get_annual_salary(101);
  DBMS_OUTPUT.PUT_LINE(v_annual);
END;
Q: Can a function have DML (INSERT/UPDATE/DELETE)?
A: Yes in PL/SQL context. But if called from SQL (SELECT statement), Oracle restricts DML to prevent side effects. Use PRAGMA AUTONOMOUS_TRANSACTION if DML from SQL context is needed.

30. Creating Packages

Why Packages?

  • Group related procedures and functions together
  • Overloading — same name, different parameter signatures
  • Package-level variables persist for the entire session
  • Better performance — entire package loaded into memory on first call
  • Encapsulation — private procedures hidden in body, public in spec
-- PACKAGE SPECIFICATION (public interface)
CREATE OR REPLACE PACKAGE emp_pkg IS
  g_tax_rate NUMBER := 0.18;   -- public package variable (session-level)

  PROCEDURE hire_employee(p_name IN VARCHAR2, p_salary IN NUMBER);
  PROCEDURE fire_employee(p_emp_id IN NUMBER);
  FUNCTION  get_salary(p_emp_id IN NUMBER)   RETURN NUMBER;  -- overloaded
  FUNCTION  get_salary(p_name   IN VARCHAR2) RETURN NUMBER;  -- overloaded
END emp_pkg;
/

-- PACKAGE BODY (implementation)
CREATE OR REPLACE PACKAGE BODY emp_pkg IS

  PROCEDURE hire_employee(p_name IN VARCHAR2, p_salary IN NUMBER) IS
  BEGIN
    INSERT INTO employees (first_name, salary) VALUES (p_name, p_salary);
    COMMIT;
  END;

  PROCEDURE fire_employee(p_emp_id IN NUMBER) IS
  BEGIN
    DELETE FROM employees WHERE employee_id = p_emp_id;
    COMMIT;
  END;

  FUNCTION get_salary(p_emp_id IN NUMBER) RETURN NUMBER IS
    v_sal NUMBER;
  BEGIN
    SELECT salary INTO v_sal FROM employees WHERE employee_id = p_emp_id;
    RETURN v_sal;
  END;

  FUNCTION get_salary(p_name IN VARCHAR2) RETURN NUMBER IS
    v_sal NUMBER;
  BEGIN
    SELECT salary INTO v_sal FROM employees WHERE first_name = p_name;
    RETURN v_sal;
  END;

END emp_pkg;
/

-- Calling package subprograms
BEGIN
  emp_pkg.hire_employee('Alice', 60000);
  DBMS_OUTPUT.PUT_LINE(emp_pkg.get_salary(101));
  DBMS_OUTPUT.PUT_LINE(emp_pkg.g_tax_rate);  -- package variable
END;

33. Creating Database Triggers (DML)

What is a Trigger?

A PL/SQL block that fires automatically when a specific event occurs — without being explicitly called.

-- BEFORE ROW trigger — validate before insert/update
CREATE OR REPLACE TRIGGER emp_salary_check
BEFORE INSERT OR UPDATE ON employees
FOR EACH ROW
BEGIN
  IF :NEW.salary < 0 THEN
    RAISE_APPLICATION_ERROR(-20001, 'Salary cannot be negative');
  END IF;
  :NEW.last_updated := SYSDATE;   -- auto-set audit column
END;
/

-- AFTER ROW trigger — audit trail
CREATE OR REPLACE TRIGGER emp_audit_trigger
AFTER UPDATE ON employees
FOR EACH ROW
BEGIN
  INSERT INTO emp_audit (employee_id, old_salary, new_salary, changed_on)
  VALUES (:OLD.employee_id, :OLD.salary, :NEW.salary, SYSDATE);
END;
/

-- STATEMENT-LEVEL trigger (no FOR EACH ROW)
CREATE OR REPLACE TRIGGER prevent_weekend_update
BEFORE INSERT OR UPDATE OR DELETE ON employees
BEGIN
  IF TO_CHAR(SYSDATE, 'DY') IN ('SAT', 'SUN') THEN
    RAISE_APPLICATION_ERROR(-20002, 'No DML allowed on weekends');
  END IF;
END;
/

-- INSTEAD OF trigger (for views that can't have direct DML)
CREATE OR REPLACE TRIGGER emp_view_insert
INSTEAD OF INSERT ON emp_dept_view
FOR EACH ROW
BEGIN
  INSERT INTO employees (employee_id, first_name)
  VALUES (:NEW.employee_id, :NEW.first_name);
END;
/

Q: What is a mutating table error?
A: A row-level trigger cannot query or modify the same table it's triggered on. Solution: use a compound trigger or statement-level trigger.

Q: How many triggers can fire in order on one DML?
A: Up to 12 — BEFORE STATEMENT, BEFORE ROW, AFTER ROW, AFTER STATEMENT × 3 DML types. Use FOLLOWS clause to control order.

CREATE OR REPLACE TRIGGER server_error_log

Q: What is SYS_CONTEXT?
A: Returns session-level context information. USERENV namespace provides: IP_ADDRESS, SESSION_USER, DB_NAME, OS_USER, etc.

Q: Difference between DDL trigger ON SCHEMA vs ON DATABASE?
A: ON SCHEMA fires only for the current user's objects. ON DATABASE fires for all users across the entire database (requires DBA privilege).

36. Managing Dependencies

What are Dependencies?

When one object references another — a view referencing a table, a procedure calling another procedure. If the referenced object changes, dependent objects may become INVALID.

-- Check status of all objects
SELECT object_name, object_type, status
FROM user_objects WHERE status = 'INVALID';

-- Check dependencies
SELECT name, type, referenced_name, referenced_type
FROM user_dependencies WHERE referenced_name = 'EMPLOYEES';

-- Recompile individual objects
ALTER PROCEDURE my_proc COMPILE;
ALTER PACKAGE my_pkg COMPILE;
ALTER PACKAGE BODY my_pkg COMPILE BODY;
ALTER VIEW my_view COMPILE;

-- Recompile ALL invalid objects in the schema at once
BEGIN
  DBMS_UTILITY.COMPILE_SCHEMA(schema => USER);
END;
Q: What happens when a table is modified and a dependent procedure exists?
A: The procedure becomes INVALID. Oracle auto-recompiles on next call if change is compatible. If not, it stays INVALID and throws an error at runtime.

Q: Difference between direct and indirect dependency?
A: Direct — procedure directly references a table. Indirect — procedure calls another procedure that references the table.

Q: What is a fine-grained dependency?
A: From Oracle 11g, if a procedure references column A of a table, and only column B is added, the procedure stays VALID (column-level dependency tracking).
